# RP-08 — ACCOUNTING POSTING & IDEMPOTENCY INTEGRITY SPECIFICATION REPORT

## EXECUTIVE SUMMARY
This report details the architectural specification for accounting posting boundaries, idempotency, traceability, multi-currency journal balance verification, and atomic rollback protections within the Receipts & Payments module. The design mandates that every posted receipt/payment produces exactly one authoritative, balanced accounting journal entry without risk of duplicate posting during network retries or timeouts.

---

## 1. POSTING BOUNDARY & GATEKEEPER SPECIFICATION

- **Canonical GL Adapter:** Receipts & Payments MUST post through `RpLedgerPostingPort`. UI widgets and local transaction services NEVER directly insert records into `journal_entries` or `journal_lines`.
- **5-Point Gatekeeper Validation:**
  1. Entity identity, multi-tenant company scope, and active status validation.
  2. Transaction status transition validation (`unposted` $\rightarrow$ `posted`).
  3. Positive amount and currency validation ($A > 0, C_{code} \neq \emptyset$).
  4. Explicit Chart of Accounts link validation ($Account_{cash} \neq Account_{counter}$).
  5. GL Balance equality validation ($\sum \text{Debit}_{base} = \sum \text{Credit}_{base}$).

---

## 2. JOURNAL ENTRY TRACEABILITY

Every accounting journal entry generated by Receipts & Payments MUST include:
- `sourceTransactionUuid`: FK referencing `financial_transactions.uuid`.
- `companyId`: Tenant scope identifier.
- `documentNumber`: Voucher book allocation number.
- `transactionDate`: Operational transaction timestamp.
- `currencyCode` & `exchangeRate`: Transaction currency and historical exchange rate snapshot.
- `lines`: Double-entry GL lines (Debit/Credit) with `debitBaseAmount` and `creditBaseAmount`.

---

## 3. STRICT IDEMPOTENCY ENGINE

- **Idempotency Key:** `rp_post:{transactionUuid}`
- **Retry Invariance:** When a posting call is retried following a network timeout or app crash:
  1. The GL adapter checks if a journal entry with `sourceTransactionUuid = transactionUuid` already exists.
  2. If found, the existing journal reference is returned without creating a second journal entry.
  3. Returns identical result, preventing duplicate ledger entries.

---

## 4. MULTI-CURRENCY BALANCE INVARIANTS

The accounting posting engine validates double-entry equality strictly in base currency units:

$$\sum \text{Debit}_{base} = \sum \text{Credit}_{base}$$

Raw transaction currency amounts in different currencies ($USD$ vs $YER$) are converted at their historical rate ($R_{hist}$) before comparison. Direct arithmetic operations between un-converted amounts are strictly prohibited.

---

## 5. 4-WAY TRANSACTIONAL ATOMICITY & ROLLBACK

Posting execution is wrapped in a single database transaction spanning:
1. `financial_transactions` status update (`posted`).
2. `accounting_journals` entry creation.
3. `cash_movements` / register log.
4. `allocations` record.

**Rollback Rule:** If any step fails (e.g., GL account disabled, DB lock timeout), the entire database transaction is rolled back, leaving the operational transaction in `unposted` state.

---

## 6. INTEGRATION TEST MATRIX (`test/modules/receipts_payments/rp_accounting_idempotency_test.dart`)

1. **Normal Accounting Posting Traceability:** Verifies correct GL journal creation with line debit/credit matching.
2. **Idempotent Retry Execution:** Simulates posting timeout retry; guarantees exactly 1 journal entry.
3. **Duplicate Posting Prevention:** Prevents duplicate posting requests for already posted transactions.
4. **Multi-Currency GL Base Balance Enforcement:** Ensures GL debit base equals credit base for multi-currency transactions.
5. **Partial Failure Atomic Rollback:** Simulates GL failure; verifies transaction remains `unposted`.
6. **4-Way Divergence Protection:** Verifies transaction, GL, register, and allocation remain synchronized.
7. **Reversal Accounting Posting Integrity:** Reversal posts balanced offsetting GL journal entry.
8. **Sync Retry Idempotency Invariance:** Re-synchronization preserves original journal UUID and amounts.
